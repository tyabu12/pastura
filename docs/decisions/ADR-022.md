# ADR-022: Phase/Event Extension Contract — Declare Once, Compile-Force Every Projection

> **Status:** Proposed
> **Date:** 2026-07-07
> **Issue:** #993 (design). Numbered 022 — 021 is claimed by #992's in-flight
> graceful-degradation ADR. Implementation is sequenced **after #992** lands on
> main — both rework `SimulationViewModel.handleEvent` and Engine files, and
> #992 (graceful-degradation architecture) has priority. Design phases run in
> parallel by agreement on #993.
> **Context:** `SimulationEvent` (23 cases) and `PhaseType` (13 cases) are the
> product's growth axis — #909 narrate, #913 mood, #914 secret are queued, and
> #992 itself will likely add degradation-notice events. Today each addition
> must be manually mirrored across ~6+ projection surfaces, and the same class
> of parity bug has shipped repeatedly: demo-replay code-phase display parity
> (8b1a146), ScenarioDetail glyph gaps (#901/#925), glyph-expansion residue
> (#893). Issue #961 (a human checklist for "adding a new PhaseType") is the
> cost's own self-report: the tax is high enough to need a checklist. This ADR
> replaces most of that checklist with compiler and CI enforcement.

---

The pattern is exact: **every recurring parity bug came from P1/P4/P7/P8-class
sites** — projections that opted out of Swift exhaustiveness via `default:`,
raw-string switching, ad-hoc scattering, or living outside Swift entirely. The
already-exhaustive sites (P2/P3/P5/P6) have not produced this bug class.

## 2. Decision

Adopt a four-part **projection contract**. The unifying principle: *adding an
enum case must force an explicit decision at every projection surface — by
compile error where Swift can reach, by red CI where it cannot. Silent
fall-through is the defect, not the number of projections.*

### D1. The declaration point stays the two Models enums — no registry

`PhaseType` and `SimulationEvent` in `Models/` remain plain Swift enums and
remain the single declaration point ("declare once" = add the case + payload).
No runtime registry, no protocol-witness re-architecture, no code generation.

Rationale:

- ADR-020's compat gate derives capability from `PhaseType.allCases`
  (`EngineSchemaVersion.passesPhaseGate`) and its D2 drift-proof claim depends
  on `allCases` meaning "the real executable phase set of this build." A
  registry or string-typed phase kind breaks that contract outright.
- Swift's exhaustiveness checker is the strongest enforcement tool available
  and it only works on real enums.
- The census gate (P9) regex-parses `Models/PhaseType.swift` as text; keeping
  the enum in that file, in the current syntactic shape, keeps the existing
  tripwire (and its repo-root existence assertion) working unchanged.

### D2. Exhaustiveness contract for every Swift projection

Every production-code `switch` over `SimulationEvent`, `PhaseType`, or
`CodePhaseEventPayload` must be **no-default exhaustive over the enum type**.
Concretely:

- **No `default:`.** Cases that a surface intentionally ignores are grouped in
  an explicitly-listed arm with a comment stating why (the P2
  `ReplayViewModel.apply` pattern). A new case then lands in *no* arm and the
  compiler rejects the file.
- **Tiered switches are permitted iff the terminal tier is no-default
  exhaustive** (the P3 `EventLineMapper` pattern: tiers 1–2 forward via
  `default:`, tier 3 lists every remaining case). This is also the remedy for
  P1's `cyclomatic_complexity`/`function_body_length` pressure: `handleEvent`
  keeps its lifecycle tier and forwards to `handleOutputEvent`, whose
  `default: break` is replaced by an explicit list of the ignored remainder.
- **No raw-string switching over phase/event kinds in Swift.** P7's
  `ScenarioSignaturePhase.init?(phaseRawValue:)` first parses
  `PhaseType(rawValue:)`, then switches exhaustively over `PhaseType`, mapping
  the seven signature-less kinds to `nil` *explicitly*. A new phase kind then
  forces a signature decision at compile time, and the `PhaseGlyphTests`
  hand-rolled parity test becomes a redundant backstop rather than the only
  guard.

The P3 canary is thereby **preserved and generalized**: `EventLineMapper`'s
no-default terminal switch stops being a special case and becomes one instance
of the codebase-wide contract (still the only one that `swift build` rather
than `xcodebuild` checks — see §5 Residual).

Enforcement of the contract itself (beyond the one-time conversion) is by
review rule: `.claude/rules/engine.md` gains the contract statement (replacing
the drifted P10 listing — see D4), and `.claude/rules/`-aware review gates
(`code-reviewer`) check new switches against it. No mechanical gate bans
`default:` — a text gate cannot see Swift types, and the parity test (D5) plus
the shrinking projection count bound the residual risk.

### D3. One semantic core for the code-phase subset

The code-phase subset (scoreUpdate / elimination / assignment /
sharedAssignment / summary / voteResults / pairingResult / eventInjected —
plus future cases) gets a single extraction point in **Models** (a legal
Models→Models dependency), in two paired halves:

```swift
extension CodePhaseEventPayload {
  /// The one SimulationEvent → persistence/display payload mapping.
  /// No-default exhaustive: non-code-phase cases return nil EXPLICITLY.
  public init?(event: SimulationEvent)
}

extension SimulationEvent {
  /// Fallback phase kind for export bucketing when the event arrives
  /// outside a phaseStarted window. No-default exhaustive; nil for
  /// non-code-phase cases.
  public var defaultCodePhaseType: PhaseType?
}
```

The pairing is load-bearing: today each of the eight persist call sites
passes a payload **and** a hand-picked per-case fallback
(`currentPhaseType ?? .scoreCalc`, `?? .eliminate`, `?? .summarize`, …).
Extracting only the payload would leave the fallback half scattered — and a
wrong fallback silently mis-buckets rows in past-results and export, which is
itself a P4-class parity bug. With both halves in Models:

- **P4 collapses**: `persistCodePhaseEvent` lifts out of the switch arms to a
  single post-switch `if let payload = CodePhaseEventPayload(event:) { … }`
  using `event.defaultCodePhaseType` — eight ad-hoc constructions become one.
- **P2 alignment is partial by design**: `ReplayViewModel` keeps its own
  `CodePhaseLine` (replay-only concerns — pacing, defense-in-depth content
  filtering — stay VM-local) but derives its discriminator/values from the
  same payload, so the *semantic* mapping has one home. The gain here is a
  single extraction source, not code deletion.
- **P5 stays put**: `ResultDetailTimelineBuilder` / `ResumeLogReplayMapper` /
  `ResultMarkdownExporter` already consume `CodePhaseEventPayload`
  exhaustively; they gain nothing from restructuring and are already
  compile-forced. `ResumeLogReplayMapper`'s hand-maintained parity comment is
  superseded by the D5 test.

Scope guard: this unifies the **semantic mapping only**. It does *not* unify
SwiftUI row views (`ModelDownloadHostView+CodePhaseRows`'s documented
byte-for-byte replica of the live `SimulationView` helpers stays as-is).
View-level unification is a separate, device-QA-gated concern and prior work
(#901/#925 family) shows premature view merging is its own bug source.

### D4. Non-Swift consumers: forced-decision gates, or deletion

Swift exhaustiveness cannot reach P8/P9/P10/P11. Each gets the closest
available equivalent of "a new case forces a decision":

- **P8 — `jsonl_to_demo_replay.py`**: two explicit module-level sets,
  `HANDLED_EVENTS` and `IGNORED_EVENTS`; an event name in neither → **hard
  error** (today: silent drop, "no failure mode at all"). A new shell-gate
  self-test (same Ubuntu "Shell gate tests" job, same
  `scripts/tests/*-test.sh` glob) regex-extracts the **`event: "…"` string
  literals from `EventLineMapper.swift`** — the actual JSONL emit surface —
  and fails if any extracted name is absent from
  `HANDLED_EVENTS ∪ IGNORED_EVENTS`. Anchoring on the emit literals rather
  than snake_casing `SimulationEvent` case names closes three holes at once:
  no hand-maintained alias map; no contamination from `SimulationError`
  (which shares `SimulationEvent.swift` and would leak into a case-name
  regex); no divergence window when a future case's emitted name is not its
  mechanical snake_case. Case-name coverage of `EventLineMapper` itself needs
  no new gate — that is exactly the ADR-013 compile canary (P3), and the two
  cases the mapper deliberately maps to no line (`agentOutputStream`,
  `roundCheckpoint`) never reach JSONL, so P3 alone covers them. The gate
  reuses the census tripwire's structure (repo-root existence assertion, a
  synthetic-drift positive fixture, and a count-floor pin on the real file so
  regex under-extraction fails loudly instead of passing silently). Moving an
  event to `IGNORED_EVENTS` is a reviewed diff — the same "explicit ignore"
  posture as D2's listed arms.
- **P9 — census gate**: unchanged. It already forces a decision (register an
  axis or a scaffolding entry) on red CI. The contract only *documents* it as
  the phase-side non-Swift gate. Its fixtures
  (`phase_types_current.swift` etc.) remain a known, CI-caught touch point.
- **P10 — `engine.md` event listing**: **deleted**, not gated. Per
  `context-budget.md`, an enumerated list findable via `grep` in the source
  file is exactly what should not live in an always-consulted rules file — and
  it has already proven it drifts. Replaced by the D2 contract statement plus
  a pointer to `Models/SimulationEvent.swift`. A drift class is eliminated by
  removing the projection rather than defending it.
- **P11 — `EditablePhase`/`ScenarioSerializer` round-trip**: a
  `PhaseType.allCases`-driven round-trip test — for each phase kind, a
  canonical YAML fixture is loaded, passed through `EditablePhase.init(from:)`
  → `toPhase()` → serialization, and compared. A new phase kind without a
  fixture fails the test (the test iterates `allCases`, so the fixture set
  cannot silently lag). This converts the "silently drops fields" class into
  test-caught.

### D5. Cross-VM parity regression test

A fixture event sequence covering **every** `SimulationEvent` case (one
canonical instance each, in a realistic order) is fed to both
`SimulationViewModel.handleEvent` and `ReplayViewModel.apply` (via
`MockLLMService`-style deterministic setup where needed). The test asserts,
for the shared semantic subset, that both sides project the same ordered
`(kind, primary content)` tuples — comparing at the `CodePhaseEventPayload` /
semantic level, since the output types (`LogEntry` vs `ChatItem`) legitimately
differ.

Intentional divergences are **encoded as explicit expectations, not skipped**:
e.g. replay's defense-in-depth content filtering, replay's structural no-op
group (P2's "never emitted by replay source" list), and live-only concerns
(persistence, contradiction detection #916, streaming handoff). The test file
becomes the executable registry of intended asymmetry between the two VMs —
the thing the P2 header comment ("mirror of handleEvent") currently entrusts
to prose.

Because the fixture is built by exhaustively instantiating each case (a
no-default `switch` in the test builder), a new event case also breaks the
*test target* compile until the fixture and both expectations are extended.

Feasibility is already proven in-tree:
`SimulationViewModelCodePhasePersistenceTests.makeSUT()` constructs the live
VM over `DatabaseManager.inMemory()` and drives `handleEvent` directly with
synthetic events; a dozen-plus test files exercise `handleEvent`/`apply`
today. D5 generalizes an existing pattern, not a new testability surface.

### D6. `PhaseDispatcher` stays a runtime dict, pinned by test

P12's `[PhaseType: PhaseHandler]` registration is execution dispatch, not
display projection; converting it to a switch would couple `PhaseDispatcher`
to every handler type for no enforcement gain, because a
`PhaseType.allCases`-iterating test (asserting `handler(for:)` does not throw
for any case) gives the same forced-decision property at test time.
`PhaseDispatcherTests` already exists; this ADR only requires that the
allCases-loop assertion be (or remain) part of it.

## 3. Alternatives considered

- **A. Checklist only (#961 as-is).** Human discipline scaling O(projection
  sites); the incident list in the header is the empirical refutation. #961
  remains useful as the *interim* measure until this ADR's implementation
  lands (which is blocked behind #992), and is then shrunk (§6).
- **B. Single God-descriptor** (`PhaseDescriptor` struct carrying glyph +
  label + editor summary + census axis + …; one file to edit per new phase).
  Rejected: it must live in `Views/` (localized labels, SF Symbols, editor
  section builders), which strips `Models/`/`Engine/` consumers of it under
  the dependency rules, so Engine-side projections would still switch
  separately — two mechanisms instead of one. It also concentrates every
  feature's edits into one merge-conflict hot-spot, and D2 already achieves
  the same forcing function with per-surface locality. The existing
  `ScenarioConventions` + `PhaseGlyph`/`PhaseDisplayName` pattern — small,
  single-purpose, exhaustive lookup files — is the right granularity and is
  kept.
- **C. Visitor protocol** (one requirement per event case; conformers get
  compile-forced without switches). Structurally equivalent to no-default
  switches, but a 23-requirement protocol is far worse ergonomically, and a
  protocol-extension default impl would silently re-open exactly the hole
  `default:` opens — while *looking* safer. Rejected.
- **D. Code generation from a manifest** (Sourcery or a bespoke generator
  emitting the enums + stubs). Rejected: new toolchain dependency, does
  nothing for the Python/census consumers (still need D4's gates), and the
  repo's generator experience (navigation map) shows the maintenance cost of
  generator + drift-gate pairs; here the generated artifact would be *load-
  bearing source*, a step further.
- **E. Runtime phase registry keyed by string** (plugin-style extension).
  Rejected outright: breaks ADR-020's `allCases` capability derivation and
  `ScenarioLoader`'s parse-throw safety net, trading compile-time enforcement
  for runtime discovery — the exact opposite of the issue's goal.

## 4. Preserved invariants (explicit)

1. **ADR-013 canary**: `EventLineMapper`'s no-default terminal switch is kept
   verbatim and reframed as an instance of D2. Nothing in this ADR touches the
   harness's `swift build` semantics.
2. **ADR-020 gate**: `PhaseType` remains a `String`-raw, `CaseIterable` enum
   in `Models/PhaseType.swift`; `EngineSchemaVersion.passesPhaseGate` and the
   `GallerySeedYAMLTests.galleryPhasesMatchYAML` D2b pin are untouched.
   `ENGINE_SCHEMA_VERSION` bump policy (ADR-020 §4) is unaffected — this ADR
   changes *where projections live*, not *what a capability addition means*.
3. **Census gate chain** (`gallery_census.py` → `run_tests.sh` →
   `scripts/tests/scenario-factory-test.sh` → Ubuntu Shell gate tests):
   untouched, including its text-parse of `PhaseType.swift` and both fixture
   files.
4. **Replay filtering policy asymmetry** (replay content-filters
   defense-in-depth where live trusts its own filter placement): preserved and
   made executable via D5's explicit expectations.

## 5. Consequences

Scope of the promise, stated precisely: "declare once" means **no silent
miss**, not zero per-projection code. Per-surface arms (a new `LogEntry` row
here, a new `ChatItem` there) legitimately remain — the contract's value is
that the compiler or a red CI job walks the author to each of them.

**Cost of a new `SimulationEvent` case, after:** add the case (Models) → fix
compile errors at: `handleOutputEvent` terminal tier (P1′), `apply` (P2),
`EventLineMapper` (P3, via `swift build` — unchanged from today),
`CodePhaseEventPayload.init?(event:)` + `defaultCodePhaseType` (D3), the D5
fixture builder → if the
event reaches demo replays, the P8 shell gate goes red until
`HANDLED_EVENTS`/`IGNORED_EVENTS` is updated. Nothing silent remains.

**Cost of a new `PhaseType` case, after:** add the case + `requiresLLM` →
compiler forces: `ScenarioConventions` (×2), `ScenarioLoader.estimatePhase`,
`ScenarioValidator`, `PhaseGlyph`, `PhaseDisplayName`, `PhaseBlockRow`,
`PhaseEditorSheet` (×2), `ScenarioSignaturePhase` (newly, via D2) → CI forces:
census axis + fixtures (P9, unchanged), D4 round-trip fixture (P11, newly),
`PhaseTypeTests` count pin, `PhaseDispatcher` allCases test (D6). The #961
checklist's "NOT compiler-caught" list shrinks from five classes to two
(census, both **CI-red** rather than silent; round-trip fixture, **test-red**).

**Residual risks, stated honestly:**

- D2 has no mechanical enforcement for *future* switches; a reviewer-missed
  `default:` re-opens a hole until D5's fixture (which exercises every case
  end-to-end) catches the semantic gap. Accepted: the two backstops fail in
  different planes (review-time, test-time), and a type-aware lint gate is not
  buildable with the repo's text-gate toolkit.
- P3 remains invisible to `xcodebuild`-only workflows — unchanged from today;
  the existing `xcodebuild-cli.md` rule ("Engine/Models/`SimulationEvent`
  changes need local `swift build`") continues to cover it.
- P8's gate is anchored to a regex over `EventLineMapper.swift`'s emit
  literals; a reshaping of `EventLine` construction syntax could
  under-extract. Bounded: the census-tripwire structure it copies includes a
  synthetic positive fixture and a count-floor pin on the real file, so
  under-extraction fails the gate's own self-test rather than passing
  silently.
- D5's live-VM side requires `SimulationViewModel` to be drivable with a
  synthetic event sequence; if #992's rework changes `handleEvent`'s
  signature/ownership, the test adapts to whatever shape #992 lands (one more
  reason implementation waits).

## 6. Implementation staging (post-#992, PR-split)

1. **PR-A (Models + VMs, the core):** `CodePhaseEventPayload.init?(event:)`
   (D3); convert P1 to tiered-exhaustive (D2); route both VMs through the
   payload; D5 parity test. Largest PR; rebases on #992's landed shape.
2. **PR-B (PhaseType display):** P7 conversion to typed exhaustive switch;
   `PhaseGlyphTests` demoted to backstop; D6 allCases assertion if missing.
   The `[String]` gallery-metadata callsite keeps a `PhaseType(rawValue:)`
   pre-parse — unknown future raw strings still `compactMap` to nil, so
   forward-compat with newer-gallery entries is preserved (consistent with
   ADR-020's grey-out posture). Independent of PR-A; can go first if #992
   drags.
3. **PR-C (non-Swift gates):** P8 hard-error + `HANDLED/IGNORED` sets + shell
   gate; P11 round-trip fixture test.
4. **PR-D (docs):** `engine.md` — delete P10 listing, add the D2 contract
   statement; shrink #961's checklist to the two remaining CI-caught classes
   (update the issue); README/CONTRIBUTING untouched (no public-surface
   change).
