# Micro-fixtures for canonicalizer null-omit verification

Issue #220 W2 PR-B Q6 — these JSON files are **hand-written, NOT generated**
from Swift `JSONEncoder`.

## Why hand-written

Swift's `JSONEncoder` default-omits `nil` Optionals (`encodeIfPresent`
synthesis). Encoding `Scenario(simulationLanguage: nil)` produces JSON with
the `simulationLanguage` key **absent**, never with `"simulationLanguage": null`
explicit. The two files in this directory exist to exercise the
[`Canonicalizer`](../../../../commonMain/kotlin/com/pastura/models/Canonicalizer.kt)'s
null-omit policy: an explicit `key: null` MUST canonicalize to the same form
as the omitted variant.

| File | Shape | Purpose |
|---|---|---|
| `simlang_explicit_null.json` | `{"simulationLanguage": null, ...}` | Exercise the null-omit Stage 1 transform |
| `simlang_omitted.json` | `{...}` (no `simulationLanguage` key) | Reference shape after canonicalization |

Both fixtures use a stripped-down JSON object (id + language + name +
simulationLanguage only) rather than a full `Scenario` — the canonicalizer
operates on arbitrary `JsonElement` trees, so a minimal valid input is
sufficient to verify the rule. Keeping them minimal avoids drift when
unrelated `Scenario` fields evolve.

## Not regenerated by `RoundtripBaselineTests`

The Swift drift-detection suite (`RoundtripBaselineTests`) writes only the
6 Swift-generated baselines under `baselines/`. These 2 micro-fixtures
are excluded from regeneration on purpose — Swift can't produce the
explicit-null variant via standard `JSONEncoder`, and the omitted variant
without the explicit pair would not exercise the canonicalizer's
null-omit policy.

## Consumed by

`shared/models/src/commonTest/kotlin/com/pastura/models/CanonicalEquivalenceTests.kt`
asserts that `Canonicalizer.canonicalize(parse(explicit))` byte-equals
`Canonicalizer.canonicalize(parse(omitted))` — the H2 hypothesis's
null-omit dimension.
