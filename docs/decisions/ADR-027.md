# ADR-027: Generic `pairwise_payoff` Scoring Logic — Payoff Tables Move to YAML

> **Status:** Accepted
> **Date:** 2026-07-17
> **Context:** Phase 2 / i18n follow-through. `Resources/Presets/prisoners_dilemma.yaml`
> declares `language: ja` yet its `choose` options are English (`cooperate` /
> `betray`) — the last un-localized surface after #1139 localized the four ja
> gallery scenarios. The blocker is architectural, not editorial:
> `Engine/ScoringLogic/PrisonersDilemmaLogic.swift` hardcodes the payoff matrix
> as a `switch (act1, act2)` over those exact English literals, so translating
> the options silently breaks scoring. This ADR records the decision to move the
> payoff table into YAML behind a new `ScoreCalcLogic` case, what that costs
> across ADR-020/-022/-024, and why the legacy case is kept forever.
>
> **Verification basis:** every `file:line` below was read at `8949aef`.

---

## Decision

Add a generic `ScoreCalcLogic` case — `pairwisePayoff = "pairwise_payoff"` — whose
payoff table is authored in the scenario YAML rather than compiled into Swift:

```yaml
- type: choose
  options: [協力, 裏切り]
  pairing: round_robin
- type: score_calc
  logic: pairwise_payoff
  payoff:
    - when: [協力, 協力]
      points: [3, 3]
    - when: [協力, 裏切り]
      points: [0, 5]
    - when: [裏切り, 協力]
      points: [5, 0]
    - when: [裏切り, 裏切り]
      points: [1, 1]
```

`when` is matched positionally against `Pairing.action1` / `action2`; `points`
awards `[agent1, agent2]`. A pairing matching no row scores nothing — the engine
never invents a verdict.

**Precedent.** `Engine/ScoringLogic/EventReactivePayoffLogic.swift` (#931) already
establishes this shape: it matches YAML-authored `favors:` strings against agent
actions with zero engine-side token hardcoding. `pairwise_payoff` is the same
move applied to a two-sided table.

**Precondition.** This ADR depends on the `choose` value-contract change recorded
in [ADR-021 § Amendment 2026-07-17](ADR-021.md) — see § "Why the option-token
fallback is not in this ADR".

## Options

| Option | Pros | Cons |
|--------|------|------|
| **A — Generic `pairwise_payoff`, legacy case kept as a shim** (chosen) | Payoff authored in YAML; ja options unblocked; chicken / stag-hunt variants become writable with no Swift; hardcoded English confined to one legacy constant | New by-name enum value ⇒ ADR-020 bump + ADR-022 sweep + ADR-024 rules; two cases exist forever |
| **B — Localize `PrisonersDilemmaLogic`'s literals to Japanese** | One-line change | Breaks `prisoners_dilemma_en.yaml` (same logic, English options); hardcodes the *other* language; no variant support; the architectural defect survives |
| **C — Generic `pairwise_payoff`, `prisonersDilemma` deleted** | One case, no legacy surface | **Rejected — breaks shipped user data.** See § "Why the legacy case cannot be retired" |
| **D — Per-scenario custom Swift logic** | Maximum flexibility | A Swift file plus an enum case per variant is exactly the cost this ADR removes. Note this is *not* an out-of-scope rejection: `Models/ScoreCalcLogic.swift:5-6` puts custom author-supplied logic in Phase 2 — the current phase. It is rejected on merit, and `pairwise_payoff` arguably discharges the need |

## Why the legacy case cannot be retired

`ScoreCalcLogic.prisonersDilemma` is **kept indefinitely**. `Views/ScenarioDetail/
ScenarioDetailActionBar.swift:88-89` gives every preset and installed gallery
scenario a **Copy & Edit** affordance that clones the YAML wholesale:

```swift
if record.isPreset || isGallerySourced {
  NavigationLink(value: Route.editor(templateYAML: record.yamlDefinition)) {
```

The clone lands in `ScenarioRecord.yamlDefinition` — a plain text column on the
user's device. Pastura has shipped to TestFlight, so copies containing
`logic: prisoners_dilemma` plausibly exist on real devices today. Deleting the
enum case makes `ScenarioLoader` throw on those records, and the user's own saved
scenario becomes unopenable.

**No migration path exists, and this is structural, not an oversight.** ADR-020's
compatibility gates are index-time (D2 `allCases` + D3 `min_engine_version`) and
operate on *gallery index metadata*. A local Copy & Edit record never passes an
index, so **only D5's parse-throw backstop applies to it** — which is precisely
the failure being avoided. Migrating the text column would require a data
migration over user rows with no schema to key on. The case stays.

**What it shrinks to.** `PrisonersDilemmaLogic` becomes a thin shim handing a
legacy-default table to `PairwisePayoffLogic`. That table is **exactly these four
rows** — it is the game's rule set, not a compatibility hack, and PR2 must not
trim it:

| `when` | `points` |
|---|---|
| `[cooperate, cooperate]` | `[3, 3]` |
| `[cooperate, betray]` | `[0, 5]` |
| `[betray, cooperate]` | `[5, 0]` |
| `[betray, betray]` | `[1, 1]` |

## Why the current `default:` arm is a latent trap, not a live bug

`PrisonersDilemmaLogic.swift:22-36` has **three** explicit arms —
`(cooperate, cooperate)`, `(cooperate, betray)`, `(betray, cooperate)` — and a
`default:` commented `// betray/betray` that awards `1, 1`.

Today that comment is accurate. `ChooseHandler.validateAction` canonicalizes every
action into the option set before it reaches a `Pairing`, so with
`options: [cooperate, betray]` the tuple is drawn from `{cooperate, betray}²` and
`default:` is reachable *only* as `(betray, betray)`. The scoring is correct.

The defect is **conditional on localization**: with `options: [協力, 裏切り]`, no
explicit arm matches, every pairing falls to `default:`, and **all five agents are
scored as mutual defectors every round** — a fabricated verdict, silently. This is
the mechanism that makes the preset un-localizable, and it is why the fix is
architectural rather than a translation pass.

Framing this precisely matters for PR2: `default:`'s `1,1` encodes the *game rule*,
not a catch-all. The generic logic replaces catch-all-ness with row matching while
the legacy table above preserves the rule.

## Dead code removed in passing: `?? "cooperate"`

`PrisonersDilemmaLogic.swift:19-20` reads:

```swift
let act1 = pairing.action1 ?? "cooperate"
let act2 = pairing.action2 ?? "cooperate"
```

This looks like fabrication and is documented as such in the subjunctive — both
`ChooseHandler.swift:17-20` and [ADR-021](ADR-021.md) D2 (`:115-116`) say a
half-real pairing *would* flow into this default, "i.e. fabrication by another
name". **Both are stating the rationale for the guard that already prevents it,
not confessing a live bug.** `ChooseHandler.swift:86` drops any half-real pairing
outright:

```swift
// Drop the whole pairing if either member skipped (ADR-021 D2): a
// half-real pairing would fabricate the missing action downstream.
guard let out1 = output1, let out2 = output2 else { continue }
```

and `ChooseHandler.swift:90` is the sole production writer of action-bearing
pairings (verified by sweep: every other `state.pairings` touch is a read in
`RelationshipUpdateHandler` / `SummarizeHandler`, or a clear in
`SimulationRunner.swift:214` / `PrisonersDilemmaLogic.swift:40`). So
`pairing.action1` is never `nil` at `:19`.

`Pairing.action1` stays `String?`. Under the generic logic a `nil` action simply
matches no row and scores nothing, which **is** the correct degradation — so the
`??` disappears as dead code rather than being replaced.

## Why the option-token fallback is not in this ADR

Investigation surfaced a genuinely live fabrication in the same area:
`ChooseHandler.validateAction` (`ChooseHandler.swift:216-218`) maps any off-menu
action to `options[0]`, so a model emitting `裏切る` (or, today, `"Betray"` —
`EventReactivePayoffLogic.swift:53-63` records that variant emissions are routine)
is silently **scored as cooperating**. Localizing to Japanese verbs widens that
surface.

That fix is **deliberately not recorded here.** It supersedes text in two other
ADRs — ADR-021 D2 `:119-121` explicitly exempts the fallback ("The #599
`options[0]` fallback is untouched — it handles a *delivered but off-menu* answer")
and ADR-002's `Amendment 2026-06-14` names it "the correctness floor, unchanged".
It also changes the value contract for *every* `choose` consumer, not just payoff
scoring. A reader debugging a dropped action five months from now opens ADR-021 or
ADR-002; they do not open an ADR titled "pairwise payoff".

It is therefore recorded as [ADR-021 § Amendment 2026-07-17](ADR-021.md), and
**must merge before the preset-migration PR** — see § "Rollout".

## Blast radius

### Compiler-forced (ADR-022's no-default projection contract)

| Site | What decides |
|---|---|
| `Engine/Phases/ScoreCalcHandler.swift:19-35` | dispatch to the logic impl |
| `Engine/ScenarioSemanticLinter+Ordering.swift:166-184` | `scoreCalcFindings` producer-dependency rule |
| `App/ScenarioGenerationPrompt.swift:139-146` | `logicDescription` for the in-app "Copy Gen Prompt" |

### Compiler-SILENT — `==` predicates (ADR-022's gate does not cover these)

**ADR-022's contract is stated over `switch`.** An `==` comparison against an enum
case is invisible to it: adding a case compiles clean and the predicate simply goes
false. A sweep of `.logic` across `Pastura/Pastura` at `8949aef` found **exactly
two**, and both must be updated by hand:

| Site | What breaks if missed |
|---|---|
| `Engine/ScenarioSemanticLinter+Ordering.swift:105` | `pdScoreCalc` feeds `actionSignalUnreachable`, which detects a **pairings-clearing** `score_calc`. `pairwise_payoff` clears pairings identically (`PrisonersDilemmaLogic.swift:40`), so omitting it makes R4 `relationship-update-placement` **silently stop firing** — a false negative (`actionSignalUnreachable` returns `clears.contains { … }`, `:141-144`), not a spurious one |
| `Views/Components/SimulationResultCard+Model.swift:86` | selects the `.pairing` result-card layout. A `pairwise_payoff` scenario **without** a round-robin `choose` silently downgrades to `.ranking` (the adjacent `roundRobin` clause accidentally rescues the migrated preset — do not rely on it) |

Every other `.logic` site is enum-value-agnostic and needs no change:
`App/EditablePhase.swift:80,104`; `Models/Phase.swift:171`;
`Views/Editor/PhaseBlockRow.swift:39` (`rawValue ?? "—"`);
`Views/Editor/PhaseEditorSheet.swift:382-383` (picker is `allCases`-driven);
`Engine/ScenarioSerializer.swift:111`; `Engine/ScenarioYAMLPatcher.swift:176`;
`Engine/Phases/ScoreCalcHandler.swift:12` (`guard let`).

**Generalization worth carrying forward:** when adding a case to any enum ADR-022
governs, grep for `== .<case>` in addition to trusting the compiler.

### ADR-020 — schema version

Adding a by-name-parsed `ScoreCalcLogic` value fires ADR-020 §4's second bump
trigger directly. The bump is expressed as a **mechanism, not a pin**: PR2 sets
`EngineSchemaVersion.current` to *the next unused integer at its branch time* — `5` as of
`8949aef`, where the constant is `4` (`Engine/EngineSchemaVersion.swift:50`, taken by
`Persona.secret` in #1141). The concern is concurrent-branch collision, not model drift:
`4` was claimed by #1141 *during this ADR's drafting*, and PR2 branches later still. (This
is the shape `adr-writing.md` §2 recommends, though its stated scope is model-pinned DoD
thresholds; the mechanism here is closer to the ADR-number-claim problem.)

Gate coverage is asymmetric and worth stating plainly:

- **Gallery content** — D2's `allCases` phase gate does **not** fire (no new
  `PhaseType`). D3 (`min_engine_version:` at or above the bumped `current`) is the only
  proactive gate; D5's parse-throw is the backstop when a scenario omits the declaration.
- **Local Copy & Edit records** — no index, therefore **D5 only**. This is the same
  fact that makes § "Why the legacy case cannot be retired" load-bearing.
- **D3a tooling does not exist.** ADR-020 D3a asks the curation pipeline to compute
  the `min_engine_version` floor by static feature detection. Verified at `8949aef`:
  no script computes it (`min_engine_version` has zero hits under `--include='*.py'
  --include='*.sh'`), and **no `docs/gallery/` entry carries the key at all**. Any
  gallery scenario adopting `pairwise_payoff` must have the floor added **by hand**
  until that tooling lands.

### CI gates

`scripts/check-scenario-format-coverage.py` requires every `ScoreCalcLogic`
rawValue to appear as a backtick token in **both**
`web/src/content/scenario-format.{en,ja}.md`. It runs as a pre-commit sub-gate and
the "Scenario Format Coverage" CI job, and fires **the moment `ScoreCalcLogic.swift`
is staged** — so both locale specs are **PR2 files**, not documentation follow-up.

### Out of scope: KMP `shared/models`

No Kotlin change. This is consistent with existing practice, not an omission:
`shared/models/src/commonMain/kotlin/com/pastura/models/ScoreCalcLogic.kt` carries
only three cases — Swift's `eventReactive` (#931) was never ported — and no CI gate
enforces parity. The frozen fixtures cannot redden either:
`shared/models/src/jvmTest/resources/frozen-presets/prisoners_dilemma.yaml` is
pinned at merge-base `f73bc48` **by design**, per
`YamlFidelityEquivalenceTests.kt:38-49`: *"Freezing both sides keeps the
point-in-time cross-language guarantee intact and drift-proof."* Re-validating the
current presets is Stage-2/5 work tracked on #501.

### Grammar: payoff tokens are never enumerated

`payoff` / `when` values must **not** reach the GBNF grammar. Author-defined
`choose` options were once emitted as alternation literals and crashed llama.cpp's
sampler on CJK values; value constraint moved to runtime — ADR-002
`Amendment 2026-06-14 — choose value-enumeration removed (#599)` for the decision,
§12.9 for the crash mechanism. CJK payoff tokens are the *motivating* case for this
ADR, so the prohibition is load-bearing here.

## New lint rules (ADR-024)

Two rules, recorded with their carve-out in
[ADR-024 § Amendment 2026-07-17](ADR-024.md):

- **`pairwise-payoff-needs-round-robin-choose`** (`.error`) — `pairwise_payoff`
  with no preceding round-robin `choose` ⇒ empty pairings, scores never change.
  Semantically identical to R2; implemented by **sharing R2's predicate function**
  while keeping a distinct `ruleID`, because ADR-024 D3 (`:122`) declares "IDs are
  stable" and a `pd-needs-…` error on a scenario with no prisoner's dilemma is a
  worse defect than a second rule row.
- **options ↔ `payoff.when` token mismatch** — split by severity to respect D2's
  bar (`.error` = "a phase can never take effect"):
  - `.error` when **no** row is satisfiable by the option set — the phase is a
    guaranteed no-op.
  - `.warning` for individual unsatisfiable rows — the phase still scores, and
    leaving some combinations unlisted (⇒ 0 points) is a legitimate authoring
    choice.

## Consequences

**Easier**

- Chicken, stag hunt, and any other two-player payoff variant become authorable in
  YAML alone. Today each needs a new Swift file plus an enum case.
- `prisoners_dilemma.yaml` can present Japanese options to Japanese players.
- The hardcoded English pair survives in exactly one place — the shim's legacy
  table — instead of being load-bearing engine logic.

**Harder**

- Two enum cases where one would do, permanently. The shim is small, but it is a
  surface future readers must be told is legacy (its doc comment must say so).
- Every new `ScoreCalcLogic` value now costs an ADR-020 bump, a three-site ADR-022
  sweep, two hand-updated `==` predicates, and two locale spec files.
- Scenario authors can now write a payoff table that is silently wrong (mismatched
  tokens). The linter rules above are the compensating control; they did not need
  to exist when the table was compiled.

**Accepted**

- The shim's unmatched-pair semantics change: `1,1` today → `0` after. This is
  **unreachable for all shipped content** — canonicalized actions come from
  `options`, and the legacy table covers `{cooperate, betray}²` exhaustively — so
  it is a no-op in practice. The only reachable path is a user's Copy & Edit clone
  that kept `logic: prisoners_dilemma` *and* translated its `options:`; such a
  scenario scores `1,1` for every pairing today (fabrication) and `0` after (honest
  omission, and the linter now flags it).

## Rollout

Ordering is a **safety constraint**: the option-token fix must precede any preset
localization, or PR3 ships Japanese options into a fallback that mis-scores them.

| PR | Scope | Notes |
|---|---|---|
| **This PR** | ADR-027 + ADR-021 § Amendment + ADR-024 § Amendment + ADR-002 pointer | Design lock only |
| **PR2** | `Models/ScoreCalcLogic.swift`, `Models/Phase.swift` (`payoff`), new `Engine/ScoringLogic/PairwisePayoffLogic.swift`, `PrisonersDilemmaLogic.swift` → shim, `ScenarioLoader` parse, `ScenarioSerializer` emit, `EngineSchemaVersion` bump, the 3 forced switches, **the 2 `==` predicates**, the linter rules, `App/EditablePhase.swift`, `Views/Editor/PhaseEditorSheet.swift`, **`web/src/content/scenario-format.{en,ja}.md`**, tests | Web specs are PR2 — the coverage gate fires on staging `ScoreCalcLogic.swift` |
| **PR2.5** | `ChooseHandler.validateAction` + the new `SimulationEvent` case + `.claude/rules/engine.md` sweep | Per ADR-021 § Amendment. Must land before PR3 |
| **PR3** | `prisoners_dilemma.yaml` (logic + options + context prose + the `speak_all` `declared_intent` instruction), `prisoners_dilemma_en.yaml` (logic + its `:8-10` header comment, which records the English-as-source decision this ADR reverses for ja), both demo replays | See below |

**PR3's demo-replay coupling is not optional.** `Resources/DemoReplays/
prisoners_dilemma_demo.yaml:22` and `prisoners_dilemma_en_demo.yaml:22` pin
`preset_ref.yaml_sha256` over the preset's full text;
`scripts/check_demo_replay_drift.py` (the `demo-replay-drift` CI job,
`.github/workflows/ci.yml:808-822`) **fails the build** on mismatch and
`App/BundledDemoReplaySource.swift:158-160` silently skips the demo at runtime. Any
byte change to either preset — the `logic:` line alone suffices — requires
regenerating both hashes. The ja demo additionally records **30** English values (20 `action:` + 10
`declared_intent:`, measured at `8949aef`) that must be hand-localized, or the DL-time demo
replays English actions under Japanese option labels.

**PR3's `declared_intent` coupling is a silent-regression risk.**
`App/ContradictionDetectionLogic.swift:45-59` (`isContradiction`) compares
`declared_intent` against the **live** `choose` options, read via
`chooseOptions(in:)` (`:35`) and folded through a trim+lowercase `normalize` (`:61`)
— no cross-script folding. The ja preset's `speak_all` prompt currently demands
English `cooperate / betray / unclear`. Localizing `options:` without the prompt
leaves the comparison permanently unmatchable and the contradiction badge goes dark
with no error. Both move together.

## Alternatives considered

- **Localize the Swift literals** (Option B) — rejected: `prisoners_dilemma_en.yaml`
  shares the logic, so hardcoding either language breaks the other.
- **Delete `prisonersDilemma`** (Option C) — rejected: breaks shipped user data with
  no migration path (§ "Why the legacy case cannot be retired").
- **Preserve `1,1` as a shim `fallbackPoints`** — rejected: catch-all mutual-defection
  scoring is the fabrication this ADR removes, and the four-row table already covers
  every reachable pair. Recorded because the alternative is tempting and the
  reasoning is non-obvious.
- **A `min_engine_version`-gated behavior switch inside `prisonersDilemma`** —
  rejected: schema version gates *content against an engine*, never engine behavior
  against content, and local records are D5-only anyway.
- **Bundle the option-token fix here** — rejected: it supersedes ADR-021/-002 text
  and belongs where a reader would look (§ "Why the option-token fallback is not in
  this ADR").
