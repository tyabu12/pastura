Colors — Meta presets & header slots（dark）

ADR-028 § Rollout gate 1 のスライス2（15 トークン ＝ ダーク対 14 + 両外観固定 1）。左が light、右がそのダーク対。 正典は design-system.md §2.9、このカードはその視覚ミラー。 設計時はサインオフ面として値の確定に先行したが、確定後は §2.9 が上位 — 食い違ったら §2.9 が正しい。 アプリは UIUserInterfaceStyle = Light 固定なので、この配色が実機に出るのは gate 1〜5 が すべて閉じてから。
暫定の地だった（slice 4 で確定）: §2.4 の実描画面は PromoCard の --promo-bg (#FBFAF2) で、設計時この light トークンは未ペアだったため --night-bubble (#2C2F28) を暫定地に置いた。 slice 4 が --night-promo-bg (#282C24) を与え、テストのトリップワイヤが 発火して再検算された — このカードの比はすべて暫定地に対する設計記録で、 実際の地では各段が上振れする（L3 base 8.16 → 8.54、白の天井 13.60 → 14.23）。 #2A2D26〜#2F3229 の帯は前提でありアサートではなく、導出値はその わずか下に着地した。§2.12 の地は screenBackground がペア済みなので --night-bg (#1B1D17) で確定。

§2.4 梯子の向きが反転する — これがこのスライスの核心

light では L が上がるほど暗くなることで淡い地に対するコントラストが増す。 dark では同じ「強調」が明るくなる方向。だから L1→L4 は per-token の 変換式では表せず、梯子ごと設計し直している（ADR-028 § Amendment が 「機械変換不能」と名指しした唯一の項目）。

LIGHT — metaBase on #FBFAF2（暗くなる↓）

L11.8 GB / 2.9 GB3.32:1
L21.8 GB / 2.9 GB5.08:1
L3 既定1.8 GB / 2.9 GB8.19:1
L41.8 GB / 2.9 GB13.11:1

DARK — nightMetaBase on #2C2F28（明るくなる↑）

L11.8 GB / 2.9 GB3.33:1
L21.8 GB / 2.9 GB5.08:1
L3 既定1.8 GB / 2.9 GB8.16:1
L41.8 GB / 2.9 GB10.77:1

L1〜L3 は light の比率をそのまま写している。L4 だけは写せない — 淡い地は near-black で 20.06:1 まで出せるが、暗いカード面 #2C2F28 の天井は 13.60:1 で、light の 13.11:1 を再現すると余白がほぼ残らない。 ここで light の metaBaseL4 が ink と同 hex (#2D2E26) である ことが効く — ダーク側の答えは nightInk (#E8E5D8, 10.77:1) で、 天井に押し当てた値が既存ペアの答えと一致した。値を発明せずに 「L4 = 本文と同じ強さのメタ文字」という意味も保たれる。

metaDotOnL1 #8A9A6C → #A8B888消灯比 2.96:1 / light 2.03
metaDotOnL2 #7A8A5C → #B7C49C消灯比 3.42:1 / light 2.50
metaDotOnL3 #6B7852 → #C3CEAE消灯比 3.83:1 / light 3.17
metaDotOnL4 #556340 → #D5DDC6消灯比 4.50:1 / light 4.33

ドットだけ不変量が違う。 base / strong は「地に対する比」を写しているが、 ドットの仕事は地に対してではなく消灯ドットに対して読めること。 消灯ドットは moss@38% で、moss は既にペア済みなので dark では nightMoss@38%（= #5B634C）に動く。この床が light（#D0D6BF、地に対し 1.43:1） より相対的に高いので、地基準で写すと点灯/消灯の差が 2.03→1.34:1 まで落ちて ドットが機能しなくなる。
採ったのは nightMoss を起点に明るくなる梯子 — light の梯子が moss を起点に暗くなるのの鏡像で、各段の明度差をそのまま反転させている。 結果 metaDotOnL1 == nightMoss となり、light の metaDotOnL1 == moss（さらに focusRing とも同 hex）という 3者一致がダークにそのまま引き継がれた。消灯比も light を下回らない（2.96 / 3.42 / 3.83 / 4.50）。
代償を明示しておく: この置き方だと dark のドットは同じ段のメタ文字より 明るくなる（L1 で 6.40:1 対 3.33:1）。light では逆に少しだけ控えめだった （2.90 対 3.32）。ドットの機能（点灯判別）を守ると知覚重みの相対関係は保てない、という トレードオフで、機能を採っている。

§2.12 GameHeader スロット（地は --night-bg）— 2 対 + 1 固定

headerRule #C2C0AE → #4745351.76:1 / light 1.76
headerMetaInk #4A4E3D → #B2B6A28.18:1 / light 8.22
headerMetaSubdued #7B7D68 → 両外観で固定4.03:1 / light 4.04

headerRule は --night-rule（1.43:1）より強いまま — light 側で headerRule が汎用 rule より暗い（行内タイポ セパレータとして機能させる）のと同じ関係。
headerMetaInk は light で metaBaseL3 と同 hex (#4A4E3D) だが、 design-system が「偶然の一致・統合するな」と明記している通り、 ダークでは値が分かれる（#B2B6A2 対 #C7CABC）。乗る面が違う （--night-bg 対 --night-bubble）ので、同じ目標比を 別の地で解くと別の答えになる — doc の「役割で独立して進化させる」という主張が ここで実際に効いた形。
headerMetaSubdued はダーク対を持たない。L≈45% の 中間調は明地でも暗地でもほぼ同じ比になるので、自地コントラストを忠実に写した解 （4.04:1）が light 値そのものになる — 実測 #7B7D68 は --night-bg 上で 4.03:1。これは退化ではなく答えで、ADR-028 gate 1 は 「両外観で固定という記録」を designed dark value と同格の充足条件として明示している。 everyPairsTwoSidesAreDistinguishableAtTolerance が赤くなるのは 「別の値を発明しろ」ではなく「ペアにするな」という信号。
当初案は「metaBaseL1 と metaBaseL2 の中間明度」という design-system の記述を不変量として写し #8E907B (5.20:1) を置いたが、あれは light 値の 導出メモであって §2.12 が課す拘束ではない（§2.12 自身が「§2.4 とは 独立して進化させる」と宣言している）。実際それを写すと、doc が本当に述べている役割 — セパレータに埋もれない二次情報、すなわち ink との階層 — が壊れる: headerMetaInk ÷ headerMetaSubdued は light 2.032×、固定なら dark 2.031× で 保存されるのに、#8E907B では 1.573× まで潰れる。 固定値は偶然 --night-muted（#7A7768, 3.78:1）のすぐ隣に着地しており、 tok/s というアンビエント情報に相応の「静謐ティア」にそのまま乗る。

検算

ペア間隔の指標は「sRGB→線形変換後の per-RGB-channel 最小差 ÷ 0.005」 （0.005 = DesignTokensTests の resolvedComponentsMatch の許容差）。 使用前に既知ベースラインを再現確認済み — muted 11.91x / moss・focusRing 19.25x / warning 15.15x が doc の 11.9 / 19.2 / 15.2 と一致。
新規14対の最狭は metaBaseL1 の 6.8x で、 これが既存最狭 muted 11.9x を下回り全体の新しい最狭になる （テストが赤くなる床は 1.0x なので十分な余裕）。中間調どうしのペアは本質的に 間隔が狭くなる — 淡い地の上のグレーと暗い地の上のグレーは、正しく置くと近い値になる。
hex 衝突は3件（metaDotOnL1 = nightMoss = nightFocusRing、 metaBaseL4 = metaStrongL3 = nightInk）。 いずれも light 側の3者一致の忠実な写像だが、 check_design_tokens_css.py は hex の substring match なので この3行は削除してもゲートが通る — diff で目視確認する。
