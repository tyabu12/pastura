Pastura — シナリオ・アートタイル 探索ルックブック

さがすカードの「顔」を強化する探索。目標は ① 正確なエージェント数 と ② シナリオの肝になるフェーズ（vote / choose / eliminate …） を、文字でなくイラスト/記号で一目で伝えること。行＝実在シナリオ、列＝方向案（A 控えめ → B 中庸 → C 大胆）。すべて実データ（体数・フェーズ列）で描画。

色は4種まで：羊カラーは alice/bob/carol/dave の4色のみ。5体は色が循環（5匹目＝alice色）。色＝個体識別ではなく「群れ＝人数」として読ませる前提。
フェーズはまだ一覧に無い：gallery.json は agent_count / rounds のみ。フェーズ表示（B/C）は gallery.json にフェーズ要約を追加する前提（curation時にYAMLから抽出。既存 gallery scripts が解析済みなので安価）。A の単一グリフも同様に1フィールドで足りる。
フェーズ語彙：assign / speak_all / speak_each / vote / eliminate / summarize / score_calc / choose / event_inject / conditional（最大5/シナリオ）。下の凡例が肝フェーズのグリフ。

補助フェーズ(配役/発言/採点/総括)を畳み、肝だけ＝乱入→分岐→投票→脱落の4個に。さらに上限(例4)を超えたら末尾を +2 ピルに。全シナリオ4±で安定。

比較の論点 ① 体数の正確さ：A/B は群れ＝人数で5体も正確（5匹目は alice 色に循環）。C はリング配置で人数を表現（脱落者は破線・半透明で「eliminate」を兼ねられる＝3行目）。
② 肝フェーズの伝達：A は単一グリフで「何で勝つゲームか」を即伝達（最安・データ1フィールド）。B は流れ全体（議論→投票→脱落 等）が読める情報量最大。C はジャンルの雰囲気・記憶に残る紋章性が最大。
③ 実装コスト：A＝gallery.json に「signature_phase」1個追加。B＝「phases配列要約」追加＋横幅レイアウト変更（カード構造に踏み込む）。C＝同上＋円環の自前描画。
