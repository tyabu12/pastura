# Launch Transcripts — スクショ台本 & 告知コピー元ネタ

ja App Store 公開ローンチ（issue #1073 / Growth C-1、親 #1069）の告知素材として、
pastura-harness で実ローカル LLM 推論を回して事前生成した「面白トランスクリプト」の
curated 集。X 拡散 / Zenn 技術記事 / Apple フィーチャリング自薦の 3 チャネル向け。

## この文書の使い方

1. この文書で「どのラン・どの瞬間」を撮るかを決める（台本）。
2. アプリ（実機 / シミュレータ）で該当シナリオを再生し、指定の瞬間をスクショする（撮影は別ステップ）。
3. 「告知コピー素材」欄を下敷きに X / Zenn / 自薦文を書く。

## 生成条件

- **モデル**: Gemma-4 E2B（`gemma-4-E2B-it-Q4_K_M.gguf`、`ModelRegistry` pin と一致）
- **実行系**: pastura-harness（ADR-013 / `tools/harness/`、`swift build`）— 実ローカル LLM 推論
- **生成日**: 2026-07-23 / **選定**: シナリオ 4 系統 × 計 13 ラン → Opus 審査員による逐語抽出
- 各ランのシナリオ YAML パスとラン ID は各エントリ § 出典に記載
- **シナリオ選定・ラン配分・キュレーション**: Fable 相談ベース（word_wolf×4 / bokete×4 / prisoners_dilemma×3 / kinoko_takenoko×2）
- **ラン ID の `_N` は harness の「ラン番号」であって、アプリ内シナリオ ID ではない**（例: `word_wolf_4` = word_wolf シナリオの 4 回目のラン）。撮影時にアプリで開くべきシナリオ名・入手経路は各エントリ § 出典と下記 § 優先順位一覧「アプリ内での開き方」を参照。

## 免責・編集ポリシー

- トランスクリプトは**実生成物・無編集**。省略は `[…]` で明示。誇張・創作の追加は禁止。
  （フィーチャリング自薦にも使う文書なので、事実でない主張はここに書かない。）
- **逐語出力は AI（Gemma-4 E2B）が生成したもの。Pastura の編集上の声（editorial voice）や公式見解として提示しない。**
  告知では「AI がこう言った」という帰属を保ち、Pastura が主張しているかのように見せない。
  これはアプリ内 ADR-005 ContentFilter の対象外（外部チャネルに出す文書なので機械的な安全網が無く、この人手確認が唯一のゲート）。
- **品質は確率的**。同条件で再実行してもこの内容は再現しない（当たりガチャ）。
  画面化は「リプレイ変換」または「再現ラン当たり待ち」のいずれか — 各エントリの撮影指示で指定。
- 生ラン（JSONL / 整形 .md）はセッションローカルの一時領域にのみ存在し永続保存していない。
  **本ファイルの逐語ブロックが唯一の耐久記録**。

## ライブ推論画面（実機撮影）— 別アセット（curated transcript ではない）

**位置づけ**: 上の①〜④は「事前生成した当たりトランスクリプトを結果画面（`ResultDetailView`）にシードして撮る」curated アセット。これは別枠で、**推論が今まさに走っている生画面（`SimulationView`）を実機で撮る**プロセス／ヒーローショット。狙いは「本当に端末で今動いている生の画面」— 特に Zenn（ローカル LLM 開発者層）向けに、ライブ streaming と実測 tok/s が最強のプルーフポイントになる。結果ショットが「オチ（🎯 ウルフ発見！）」を見せるのに対し、これは「過程（オンデバイスで複数体が今考えている）」を見せる。両方揃うと記事が強い。

**なぜ自動化しないか**（`marketing-shots.sh` / `MarketingShotTests` を拡張しない理由）:
- `--ui-test` 起動は `MockLLMService` 固定で、mock は completion トークン数を返さない → ヘッダの実測 tok/s が**そもそも表示されない**。
- iOS シミュレータは量子化 GGUF 推論を実行できない（`.claude/rules/engine.md` § "iOS Simulator cannot run quantized inference"）→ シミュレータ経路に実測 tok/s は原理的に存在しない。
- mock で実エンジンを完走させるには、非永続で失われた発話を捏造して埋める必要があり、§ 免責・編集ポリシーの「創作禁止」と衝突する。

→ このショットの商品価値は「逐語の忠実再現」ではなく「**機構が本物であること**（streaming／実測 tok/s／完全オフライン）」なので、決定論は要件でない。実機で普通に回して手で撮るのが正しく、内容はどのランでもよい（当たりを待つ必要はない）。

### 撮影手順
1. **モデル DL 完了を先に確認**してから機内モードを ON にする。Gemma-4 E2B（~3.1 GB）が端末に未 DL の状態で機内モードにすると、ラン自体を開始できない。DL 済みを確認 → 機内モード ON、の順序を守る。
2. 端末: **iPhone 16e**（8 GB RAM、`ModelRegistry.minRAM` 6.5 GB ゲート通過）/ ロケール ja / ライト（アプリは固定パレットの実質ライト専用）。
3. **バンドル preset「ワードウルフ」**を preset ピッカーから開いて実行（一般名詞のゲームで素材として最も安全＝①と同シナリオ）。
4. **撮りどころ = 2 人目以降の発話がストリーミング途中の 1 コマ**。実測 tok/s は「初回推論が完了した後」にしか値を持たない（`SimulationViewModel.averageTokensPerSecond`）。値が nil の間はヘッダの tok/s フラグメントが**まるごと非表示**になる（`GameHeader` は非 nil のときだけ tok/s を描画。`— tok/s` のようなプレースホルダは出ない）ため、1 人目のストリーミング中は tok/s が一切出ない。**2 人目以降**なら「書きかけで途切れている本文」と「ヘッダの実測 tok/s」が同一フレームに共存する — これがこのショット唯一の存在理由。
5. 静止画 1〜2 枚に加えて、**10 秒前後の画面収録**も撮る。ストリーミングは時間軸の現象なので、動画/GIF を貼れる Zenn では収録が主、静止画は X・記事サムネ用のフォールバック。

### 合格条件チェックリスト（1 つでも欠けたら撮り直し）
- ☐ 本文が明らかに**途切れている**（生成途中＝ライブの証拠）
- ☐ ヘッダに **実測 tok/s が実数値**で出ている（tok/s がまだ出ていない＝1 人目で撮った早すぎフレーム。値が nil の間は tok/s 表示ごと消えるので、プレースホルダも出ない）
- ☐ ステータスバーに**機内モードアイコン**（＝完全オフラインの一枚証明）
- ☐ **実行中ピル**＋ ROUND n/N ＋フェーズ名が見えている

### 写る要素の意図（入れる／外す）
- streaming 途中本文 → ライブの核心。**必須**。
- 実測 tok/s → dev 層への proof point。**実測のみ**（§ キャプション規律）。
- 過去発話行の減光（生成中の行にフォーカス）→ ライブ状態の正直な描画。入れてよい。
- 直前 committed 行の ▸ THINKING（inner voice）→ クラウドチャット UI との差別化点。`word_wolf.yaml` は speak_each に `inner_thought` を宣言しているので描画される（宣言が消えれば ▸THINKING も出ない）。入れてよい。
- play/pause コントロールバー → 「観測を操作できるアプリ」の証拠。入れてよい。
- タブバー非表示（フォーカスモード、ADR-017）→ 没入 chrome。自動でそうなる。
- result card / scoreboard → **写さない**（完了物は結果ショット①の領分）。

### キャプション規律（公開前の唯一の人手ゲート — § 免責・編集ポリシーと同じ規律）
- **画面／キャプションに実測以外の数値を出さない。** tok/s は実機実測値のみ。地味な値（十数 tok/s）でも隠さず、盛らない。
- キャプションに**端末名（iPhone 16e）とモデル名（Gemma-4 E2B）を明記**する（画面ヘッダには出ないため）。
- **別ラン帰属 NG**: このライブショットは①word_wolf_4 とは**別ラン**（当たりガチャの逐語とは無関係の実行）。①の逐語や「🎯 ウルフ発見！」の結果と**同一ランであるかのように接続しない**。記事本文でも「この画面のランがこの結果を出した」と読める並べ方をしない。
- **素材の役割分担**: iPhone 16e は 6.9″ 端末ではないので、**Apple フィーチャリング自薦／App Store 掲載素材にはこのライブショットを使わない**（そちらは既存の 6.9″ 結果ショット①③で充足）。ライブショットの用途は **Zenn・X**。
- 品質は確率的（§ 免責・編集ポリシー）。狙いのフレームが撮れないランもあるので、複数ラン試す前提で。
