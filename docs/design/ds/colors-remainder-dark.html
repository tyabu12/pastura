設計判断

page は沈み、promoBackground は浮く。light では両方とも body 地よりわずかに below（1.099 / 1.047）で同じ向きだが、dark では nightPage が引き続き below（1.099）である一方 nightPromoBackground は body 地に対して above（1.195）に転じる — page は画面の奥に退く背景の役割を night でも保つのに対し、promoBackground はカードとして手前に浮く役割を night で強めて保つ、という向きの違いがそのまま比の違いになる。

promoBorder と mossSoft は方向が反転する。境界線は自分の乗るカードに対する量を light/dark 双方で 1.204 のまま持ち越すが、向きは反対にした。light の向き（カードより暗い）を保つと #1A1C17 になり、カードに対しては 1.207 で通る一方、背後の地に対して 1.010 まで縮んでカード端が溶ける — 通したい面ではなく、通したくない面で落ちる。だから向きを反転させ、出荷値 nightPromoBorder は地に対して 1.440 above に座る。rule → nightRule（1.324 below → 1.425 above）と同じ形で、原初の 8 対が既に踏んでいた反転。

§2.3 の 4 段は順序ごと反転する。light は ink < dark < moss < soft の明度順だが、dark は soft < moss < dark < ink に並び替わる。nightMossDark（body 地比 8.902）は nightMoss（7.999）より明るい — dark 側の「濃い moss」が「基準の moss」を追い越す。

inkOnAccent は dark で白ではない。MD3 は primary が tone 40→80（moss → nightMoss 相当）に上がるとき on-primary の tone を 100→20 へ落とす。最小消費が 9pt/9.5pt のラベルであるため、置いた基準は白ではなく WCAG AAA 7:1（mossDark 上 7.117）。nightBubble と同値になったのは結果であって、継承して持ち越した一致ではない。

mossSoft の色相は moss ファミリへ移した。light の 47.7° というクリームがかった色相を dark でもそのまま保つと 5% 輝度ではアンバーに読め、nightWarningSoft と衝突する。nightMossSoft は 80.9° の moss 系へ寄せて回避した。

設計せずに一致した 2 つの関係。CTA ラベルの比（screenBackground on mossInk → nightBackground on nightMossInk）は 10.190 → 10.187 とほぼそのまま生き残り、moss バッジ（mossDark on mossSoft, 2.911 → 5.685）は §2.6 の 4 ペア（light 5.39–5.98 / dark 7.69–8.37）の中で両外観とも最も静かなペアであり続けた。どちらも個別のトークンを追いかけて設計した帰結であって、比そのものを目標に置いたわけではない。

nightPage #11130F はパレット全体で最も暗いトークン。シートは持ち上がるという iOS の慣習に対し、その消費先はシートを一段暗くする側に置かれている — ADR-028 gate 4 の実機 QA でフラグを立てて確認する。
