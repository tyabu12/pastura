# ADR-021: Graceful Degradation of LLM Turn Failures

> **Status:** Accepted
> **Date:** 2026-07-08
> **Context:** A single LLM-call failure anywhere in a run aborts the whole simulation (#992); runs cost minutes to tens of minutes, and the app is pre-submission with zero install base, so a late-run total loss for a first real user (App Review included) is a launch-critical risk.

## Context

### The all-or-nothing failure path today

Every phase handler's throw is caught in exactly one place — the catch-all in
`SimulationRunner.executePhases` (`Pastura/Pastura/Engine/SimulationRunner.swift:357-375`) —
which emits `.error(...)` and returns `true`, terminating the round loop. `.simulationCompleted`
is never reached, and the App layer's terminal-status precedence
(`SimulationViewModel.terminalStatus`, `SimulationViewModel.swift:1279-1288`) maps any
non-cancelled `.error` to `SimulationStatus.failed`. There is no per-phase or per-turn
containment: one flaky parse in round 3 of 10 marks the entire run failed.

`Engine/LLMCaller.swift` retries each turn up to `maxRetries = 2` (3 attempts, shared budget
across four retry causes: `sampler_crash`, `parse_failed`, `empty_field`, `language_mismatch`).
Exhaustion outcomes are already asymmetric:

| Cause | On budget exhaustion | Run survives? |
|---|---|---|
| `parse_failed` | `throw SimulationError.retriesExhausted` (`LLMCaller.swift:114-121`) | **No** |
| stream/generation error (non-retryable) | `throw SimulationError.llmGenerationFailed` (`LLMCaller.swift:98`) | **No** |
| `empty_field` | falls through, returns the empty-field output (`LLMCaller.swift:127-131`) | Yes (silent) |
| `language_mismatch` | emits informational `.languageMismatch` event, returns output (`LLMCaller.swift:140-145`) | **Yes (explicit)** |

Two error classes already bypass the budget by design: `LLMError.suspended` is consumed
inside `consumeStreamWithSuspendRetry` (background/foreground cycles are free), and
`LLMError.invalidGrammar` is fail-fast in the budget sense — a deterministic engineering bug
must not burn 3 flaky-inference retries. Note, however, that today *every* non-retryable
stream error — `invalidGrammar` and `notLoaded` included — is still type-erased into
`SimulationError.llmGenerationFailed(description:)` at `LLMCaller.swift:98`; fail-fast means
"no retry", not "escapes typed". D3 below changes that wrap.

### The codebase is already half-defensive

The Engine's **code phases and downstream consumers already tolerate missing inputs**
(verified per consumer at draft time):

- `VoteHandler` drops out-of-candidate ballots from the tally while keeping the raw value
  for observability (`VoteHandler.swift:65-74`, #524).
- `ChooseHandler.validateAction` falls back to `options[0]` for off-menu actions
  (`ChooseHandler.swift:156-159`, #599).
- `EliminateHandler` no-ops on empty `voteResults`; `WordwolfJudgeLogic` emits a
  "No votes recorded" summary and skips scoring; `VoteTallyLogic` ignores unknown names;
  `EventReactivePayoffLogic` no-ops on a missing favored variable.
- `ConditionEvaluator` resolves absent variables (e.g. `vote_winner` with no votes) to a
  `false` comparison with a `.summary` warning — routing to the `else` branch, never throwing.
- `ReflectHandler` writes `notes_<name>` only when non-empty, so a failed/empty inference
  cannot erase a previous round's memo (`ReflectHandler.swift:65-72`).

Only the six LLM phases (`PhaseType.requiresLLM == true`: `speak_all`, `speak_each`, `vote`,
`choose`, `reflect`, `whisper` — `PhaseType.swift:51-59`) lack containment, and
`.languageMismatch` (`SimulationEvent.swift:163-183`) already models the target pattern:
an **informational event + continue**, explicitly documented as "unlike `.error`".

### Partial-progress durability already exists

`TurnRecord` rows persist per-output through a serial queue regardless of the run's eventual
status, and `.roundCheckpoint(state:)` persists a resumable snapshot at each round boundary.
When a run dies, everything up to the failure is already durably stored — the missing pieces
are (a) not throwing the rest of the run away, and (b) an honest status/display for the gap.

### Related

- #751 — recoverable parse flakiness (stray trailing `}`, empty output); the dominant
  *transient* failure class this ADR contains. Parser-side fixes remain tracked there.
- #680 — Metal reload hang (closed); an example of the *systemic* class this ADR must NOT
  paper over turn-by-turn.
- ADR-017 — `SuspendController`: the existing precedent for "interrupt without failing the run".

## Options

### Containment altitude

| Option | Pros | Cons |
|--------|------|------|
| **A. Runner-level phase skip** — catch in `executePhases`, consult a per-`PhaseType` policy table, skip the phase | Single choke point; no handler edits | Whole-phase granularity: one agent's flaky turn discards all other agents' work in that phase; cannot express per-pair (choose) or per-ballot (vote) semantics |
| **B. Handler-level per-turn containment** (chosen) | Matches the natural failure unit (one agent × one phase); aligns with existing per-ballot/per-action precedents; other agents' turns in the same phase survive | Touches all six LLM handlers (mitigated by a shared gate helper) |
| **C. `LLMCaller` returns a degraded marker instead of throwing** | No handler catch logic | Pushes phase semantics into a layer that has none; every call site must branch on the marker; blurs the throw contract with systemic errors |
| **D. Status quo + resume-proposal only** | Smallest diff | Does not help the common case (one transient flake mid-run still kills the run; resume costs a user round-trip and re-runs the whole interrupted round) |

### Degraded-run status representation

| Option | Pros | Cons |
|--------|------|------|
| **New `SimulationStatus.completedWithGaps`** | Queryable at the status level | Ripples every status switch, filter, and localization for what is a quality annotation, not a lifecycle state; blurs resume/cancel logic |
| **Keep 5-way status + degradation metadata on the record** (chosen) | Status stays a pure lifecycle taxonomy; additive column migration; UI badge drives honesty | "Has gaps" needs a column read, not a status compare |

## Decision

**D1 — Contain failures per turn, inside the LLM handlers.** A failed LLM call degrades to a
*skipped turn*: that agent's contribution to that phase is omitted and the phase continues
with the remaining agents/pairs. The phase still emits `.phaseCompleted`; the round and run
continue. Implemented via a single shared gate (working name `TurnFailureGate`, an
Engine-layer type carried on `PhaseContext`) so the catch/classify/count logic exists once,
not six times:

```swift
guard let output = try await context.turnGate.attempt(
  agent: persona.name, phaseType: context.phase.type, emitter: context.emitter,
  work: { try await llmCaller.call(...) }
) else { continue }  // turn skipped — gate already emitted .turnSkipped
```

**D2 — Degrade by omission, never fabrication.** A skipped turn writes nothing synthetic:

- `speak_all` / `speak_each`: no `conversationLog` entry, no `.agentOutput`.
- `vote`: abstention — no ballot recorded, no tally contribution (extends the #524 tally-drop
  precedent from "invalid ballot" to "no ballot").
- `choose` (round-robin): the **whole pairing is dropped** — a pairing with one real and one
  defaulted action would flow into `PrisonersDilemmaLogic`'s `?? "cooperate"` default, i.e.
  fabrication by another name. The partner's already-emitted utterance stays visible, and the
  partner's successful action remains in `state.lastOutputs` (legitimately consumable by
  `EventReactivePayoffLogic`); only the *pair-based* scoring interaction is omitted. The
  `lastOutputs` clear below applies to the **failed member only**. The #599 `options[0]`
  fallback is untouched — it handles a *delivered but off-menu* answer; a failed call
  delivers nothing to canonicalize.
- `choose` (individual) / `reflect`: no write for that agent/turn.
- `whisper`: a skipped utterance **ends that pair's exchange early** — the remaining
  sub-round turns for that pair are not attempted (a partner "replying" to a missing
  utterance would desync the exchange). Turns already exchanged stand, and the
  `whispers_<name>` keys update under the existing overwrite semantics.

Additionally, a skipped turn in a `lastOutputs`-writing phase (speak/vote/choose) **clears**
`state.lastOutputs[agent]` rather than leaving the previous phase's entry readable: stale
decision data must not leak into consumers keyed on it (`EventReactivePayoffLogic` reads
`lastOutputs[name].action`; `RelationshipUpdateHandler` reads `.vote` — a stale prior-round
action would be silently scored as current). Private-memory keys (`notes_`, `whispers_`,
`relationships_`) retain their previous values, consistent with the existing `ReflectHandler`
non-empty guard: memory persists, decisions don't go stale.

Downstream tolerance for the resulting absences is the existing, verified behavior catalogued
in Context ("already half-defensive") — this ADR adds no new downstream defaults.

**D3 — Classify failures at the `LLMCaller` boundary into three classes.**

| Class | Members | Gate behavior |
|---|---|---|
| **Transient** (turn-degradable) | `SimulationError.retriesExhausted`; `SimulationError.llmGenerationFailed` wrapping transient stream/generation errors; `LLMError.networkError` (Ollama dev backend — a flaky HTTP call is transient; a dead server trips the D4 breaker within 3 turns, acceptable for a dev-only path) | Skip the turn (D1/D2), count it (D4) |
| **Systemic** (run-fatal) | `LLMError.invalidGrammar` (deterministic engineering bug — existing no-retry rationale), `LLMError.notLoaded` | Rethrow immediately → existing catch-all → `.error` → `.failed` |
| **Control-flow** (never degraded) | `CancellationError` / `Task` cancellation; `LLMError.suspended` (already consumed inside `consumeStreamWithSuspendRetry`, never escapes) | Rethrow immediately (cancellation); n/a (suspended) |

`LLMError.loadFailed` is deliberately **not** in the systemic set: it is thrown only from
`loadModel`, which the App layer calls and handles *before* the run starts — it cannot reach
the `LLMCaller` boundary, and a gate arm for it would be dead code.

Mechanism: today `LLMCaller.swift:98` eagerly wraps every non-retryable stream error —
`invalidGrammar` and `notLoaded` included — into
`SimulationError.llmGenerationFailed(description:)`, erasing the type the gate needs.
`LLMCaller` will rethrow the systemic `LLMError` cases **typed** (unwrapped); the runner
catch-all already wraps any non-`SimulationError` for the `.error` event
(`SimulationRunner.swift:370-374`), so user-facing messages are unchanged on the run-fatal
path. The gate pattern-matches: systemic/cancellation rethrow, everything else degrades.

**D4 — Run-level circuit breaker: 3 consecutive skipped turns → run-fatal.** The gate keeps a
consecutive-skip counter (reset on any successful turn, shared across phases within one run).
When a degradable failure would be the 3rd consecutive skip, the gate instead throws a new
`SimulationError.turnFailureLimitReached(consecutiveCount:)` — surfacing through the existing
abort path with an honest, localized description. Rationale: each skipped turn costs up to
3 attempts of inference latency; without a breaker, a systemically-dead backend that evades
the D3 taxonomy (e.g. every call times out) would grind through the remaining scenario for
tens of minutes emitting nothing — a zombie run is worse UX than an early abort. The counter
is runner-execution state, **not** part of `SimulationState` (a resumed run starts at 0; no
Codable/checkpoint migration). The limit is a named constant with a doc comment, not a
tuning contract — it is a UX bound, model-independent, so no mechanism-contract framing is
needed (`.claude/rules/adr-writing.md` §2 consulted).

Gate mechanics (load-bearing for "shared across phases"): `PhaseContext` is a `Sendable`
struct rebuilt per phase in `executePhases`, so a value-type gate would reset the counter at
every phase boundary and neuter the breaker. The gate is therefore a **`Sendable` reference
type** (`final class` with `OSAllocatedUnfairLock`-protected state — the `SuspendController`
pattern), created once per run by `SimulationRunner` and the **same instance** injected into
every `PhaseContext`. Invariant: handlers that dispatch sub-phases (`ConditionalHandler`)
must thread the parent context's gate into the sub-phase contexts — a fresh gate inside a
branch would silently reset the count.

**D5 — Explicit, informational `SimulationEvent.turnSkipped`.** New case
`turnSkipped(agent: String, phaseType: PhaseType, cause: String)`, modeled on
`.languageMismatch`: informational, not `.error`; the simulation continues. `cause` carries
the diagnostic description (same register as `llmGenerationFailed`'s payload — English,
non-localized); the App layer renders its own localized narration line in the **live** log.
No silent degradation.

Per-turn honesty is **live-only**; the durable post-hoc signal is the aggregate
`degradedTurnCount` (D6), counted App-side from `.turnSkipped` events — the same shape as
the existing `languageMismatchCount`. This follows the `.languageMismatch` precedent exactly:
informational events are not persisted today, and `ReplayViewModel` deliberately no-ops
`.languageMismatch` on replay. Persisting per-turn skip markers (e.g. sentinel `TurnRecord`
rows) was considered and rejected: sentinel rows would pollute every transcript-rendering
consumer of the `turns` table for marginal value once the live narration + aggregate badge
exist. #992's honesty requirement ("no silent degradation") is met by the live narration plus
the post-hoc badge; if field usage later shows per-turn post-hoc placement matters, that is
an additive follow-up (a nullable marker column on `turns`), not a rework.

**D6 — Run status taxonomy unchanged; degradation recorded as metadata.** A run that reaches
`.simulationCompleted` with skipped turns persists as `SimulationStatus.completed` plus a new
additive `SimulationRecord` column `degradedTurnCount INTEGER NOT NULL DEFAULT 0`. Results
and history UI show a badge/annotation when the count is > 0 ("completed — N turns skipped").
A circuit-breaker abort persists `.failed` exactly as today. The five-way `SimulationStatus`
(`SimulationStatus.swift`) is untouched.

**D7 — Retry budget unchanged.** `maxRetries = 2` shared across causes stays, as do the
`suspended` / `invalidGrammar` exemptions. Per-cause budgets are rejected: once a turn
failure is cheap (a skip, not a dead run), extra budget bookkeeping buys little; and #751
explicitly defers retry-budget changes for the empty-output sub-class pending on-device
root-cause. The `empty_field` / `language_mismatch` degraded-return paths are also unchanged
(they already continue; re-plumbing them through `.turnSkipped` would change delivered-output
semantics for no containment gain).

**D8 — Resume proposal for failed runs: deferred final increment.** For a `.failed` run
holding a valid round checkpoint (`stateJSON` + `currentRound`), offer "resume from round
N+1" in the results UI, reusing the paused-run resume machinery
(`SimulationRunner.run(resumingFrom:startRound:)`). This rescues the circuit-breaker/systemic
case that D1–D5 deliberately do not contain. It ships last and may be spun off to its own
issue if, after D1–D6 land, field behavior shows it is rarely reachable — decide at PR4
planning, not silently.

## Rationale

- **Per-turn is the natural failure unit.** The existing precedents the issue names —
  tally-drop, `options[0]`, the reflect non-empty guard, `.languageMismatch` — are all
  per-agent/per-value containments, not phase- or run-level ones. D1 extends the pattern
  rather than inventing a parallel policy layer.
- **Omission composes with what's already there.** Every downstream consumer was verified to
  tolerate absent inputs (Context). Fabricated defaults would *reduce* honesty and would need
  new per-phase policy definitions; omission needs none.
- **The taxonomy preserves the two existing fail-fast rationales.** `invalidGrammar` and
  cancellation abort exactly as today; the suspend path is untouched. The design changes
  behavior only for the transient class where retry-then-die is currently the sole option.
- **The breaker bounds the worst case in both directions.** Without it, degradation converts
  "fail fast" into "fail slow" for systemic outages; with it, worst-case wasted time is
  bounded at ~3 turns × 3 attempts beyond today's behavior, while a single mid-run flake — the
  common case per #751 — costs one narrated gap instead of the whole run.
- **Status-as-metadata keeps the DB and UI honest without a taxonomy fork.** `completed` still
  means "all rounds ran to the end"; the badge carries the quality signal; `failed` still
  means "did not reach the end". No consumer of `SimulationStatus` needs re-auditing.

## Trade-offs

**Easier:**

- First-user / App Review experience: a transient flake yields a narrated gap, not a dead run.
- Debugging honesty: `.turnSkipped` events + `degradedTurnCount` make flakiness measurable in
  the field (complements #751's quantification).
- Future backends (LiteRT-LM, new models): containment semantics are backend-agnostic;
  nothing pins to Gemma/llama.cpp behavior.

**Harder / costs:**

- Scenario semantics under gaps: a skipped vote can flip an elimination or route a
  `conditional` to its `else` branch. This is accepted — it is exactly what the existing
  absent-variable semantics already do — but transcripts become harder to reason about
  without reading the skip narrations.
- Six handlers gain a gate call and skip bookkeeping; tests must cover per-handler skip
  behavior and the cross-phase breaker. Failure injection uses MockLLMService's **existing**
  `throwErrorOnNextGenerate(_:count:)` API (typed `LLMError` injection — which is also why
  the D3 typed rethrow is a prerequisite for exercising the systemic arm in tests).
- A new `SimulationEvent` case ripples to the ADR-013 harness `EventLineMapper` (its final
  switch tier is `default:`-free — the intended compile canary; the earlier tiers carry
  `default:` and also need a routing decision) and to App-layer event handling,
  `ContentFilter` pass-through, and localization.
- The D3 typed rethrow slightly widens `LLMCaller`'s throw surface (typed `LLMError` escapes
  where today everything is pre-wrapped); the runner catch-all's existing wrap keeps
  user-facing behavior identical, but future callers must not assume `SimulationError`-only.

## Non-goals

- Parser robustness fixes and empty-output root-cause (#751 — orthogonal, stays open).
- Model load/reload stability (#680 — closed; systemic class remains fail-fast here).
- Per-cause retry budgets (rejected, D7).
- Any scenario-YAML surface or `PhaseType` change — hence **no `ENGINE_SCHEMA_VERSION` bump**
  (ADR-020's gate keys on scenario capabilities, which are unchanged; this ADR alters
  failure-path behavior only, not the semantics of successful execution).
