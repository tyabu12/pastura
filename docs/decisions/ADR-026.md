# ADR-026: LLM-Dynamic Word Wolf Topics — Near-Term No-Go, Static Curation Preferred

> **Status:** Accepted
> **Date:** 2026-07-16
> **Context:** Phase 2 / sim-interestingness (#906). Word Wolf hands every
> player a secret topic word and one player (the "wolf") a *different but
> related* word — the pair must be close enough that talk overlaps yet
> distinguishable with care (e.g. りんご / みかん). The shipped
> `word_wolf.yaml` hardcodes this pair as a static `words:` array consumed by
> the code-phase `assign` (`source: words`, `target: random_one`); today it
> holds one pair, so every game is りんご / みかん. This ADR records the
> decision on whether to instead have the on-device LLM **generate** the pair
> dynamically per playthrough, the harness evidence behind it, the reusable
> principle it establishes, and the deferred design sketch — so the next
> attempt (on a stronger model) doesn't replay the investigation from scratch.

---

## Decision

1. **Do NOT build dynamic LLM topic generation now.** `word_wolf` keeps the
   static `words:` mechanism unchanged.
2. When topic variety is wanted, the near-term answer is **expanding the
   curated static `words:` pool** — not LLM generation. (No shipping value
   during the app's first-review wait, so even this is deferred, not urgent.)
3. Record the **general principle** (below), the **deferred design sketch**,
   and the **revisit trigger** so a future attempt on a stronger model starts
   from here.

`Status: Accepted` scopes to this **No-Go / defer** decision only — NOT to the
deferred `generate`-phase sketch below, which is explicitly non-binding.

## Why — the harness evidence

**Provenance (for the future revisit):** measured this session (2026-07-15/16)
on `pastura-harness` (ADR-013) driving **real Gemma 4 E2B (Q4_K_M)** llama.cpp
inference. Probe ladder: open-category generation (n=25) → **~16-20%** usable
pairs; fixed-category generation (each agent pinned to one genre) → **ja ~60% /
en ~72%**; then a gate at **n≈100 per category × 5 categories × 2 languages**.
Each sample was one LLM call emitting `{theme, majority, minority}` with no
conversation-log context (independent draws). Raw transcripts were session
scratch (not committed); re-run the same probes to reproduce.

Three findings drove the No-Go.

### 1. A pure mechanical validator is not viable — three failure modes

A no-LLM-judge validator (normalize katakana→hiragana + equality, substring
containment, dedup) was measured against the gate output. It fails three ways,
and the misses are exactly the "unwinnable game" class:

- **Misses semantic part-of and script homographs.** ja animals: `カメ ↔ 甲羅`
  (turtle vs its own shell, part-of) **52%** of draws, `ネコ ↔ 猫` (same word,
  katakana vs kanji) **17%**; en: `Macaron ↔ Macaroon`, `Submarine ↔
  Submersible`, `Pencil Lead ↔ Graphite`. In ja animals the filter caught **1
  of ~70** breakages (the lone string-overlap case `カメの甲羅 ⊃ カメ`).
- **False-positive-rejects a legitimate pair.** `Pen ↔ Pencil` — a textbook
  Word Wolf pair — is rejected by the containment rule because `pen` is a
  substring of `pencil`.
- **Passes hallucinated non-words.** ja stationery emitted `のび筆`,
  `のり番石膏` (not real words); neither same-word nor part-of, so the filter
  passes them.

Catching the missed classes needs a **semantic judge** — a reading-normalization
dictionary for homographs *and* a knowledge/LLM check for part-of — i.e. an
on-device LLM judge, which adds latency and its own reliability question on a
2B-class model. An anti-homograph **prompt** rule ("表記違いも同じ語なので禁止")
did eliminate `カメ↔亀` at the source, but the fixation merely shifted to the
part-of form `カメ↔甲羅`, which the prompt rule does not fix.

### 2. Diversity collapse

Even in clean categories the model's effective repertoire is tiny — every
category (ja and en) is dominated by 1-2 anchor pairs: `Lion↔Tiger` 51%,
`トマト↔ピーマン` 49%, `Macaron↔Truffle` 42%, `Submarine↔Ferry` 39%,
`Highlighter↔Marker` 42%. Effective distinct-usable pairs ≈ **3-5 per clean
category**, ≈ 15-20 across all safe categories. A hand-curated static list of
~30 pairs beats this on variety — at zero cost, zero safety surface, and full
test determinism. So dynamic generation *approximates a small static list*
while paying engine + safety + non-determinism costs; the "every game is fresh"
value proposition does not materialise on this model (you get `トマト↔ピーマン`
~49% of the time).

### 3. Category quality is empirical and per-language (cross-language flip)

The **same** "animals" category is catastrophic in ja (`カメ↔甲羅`) but clean
in en (`Lion↔Tiger`, `Elephant↔Rhinoceros`). A category safelist therefore
cannot be assumed to transfer across languages — it must be measured **per
language**. Clean categories observed: ja 野菜 / スイーツ, en vegetables /
animals. Weak: ja 動物 (catastrophic), ja 乗り物 / ja 文房具 / en sweets /
en vehicles / en stationery (hierarchy, synonym, or non-word prone).

## General principle (reusable beyond word_wolf)

**LLM-generated game content must clear calibration AND diversity AND
script-robustness, gated by harness measurement (ADR-013); below the bar,
prefer static curation.** This applies to any future "let the model invent game
content" proposal — the failure was not word_wolf-specific but a property of
generating structured, calibrated, deduplicated content on a 2B-class model.

## Consequences

- `word_wolf` is unchanged; static `words:` stays the mechanism. Expanding the
  pool from one pair is a cheap, separate follow-up when shipping resumes.
- **No new PhaseType** — the ADR-022 phase/event projection contract and the
  `PhaseType` ripple surface are untouched.
- **Content safety unchanged** (ADR-005): no new unfiltered-generation surface;
  curated static pairs remain the safety model.

## Deferred design sketch — NON-BINDING (not an approved contract)

Preserved for when a stronger model clears the bar. This is a *sketch*, not an
Accepted design; implementing it requires its own ADR/plan.

- **New non-diegetic `generate` LLM phase.** Emits structured
  `{majority, minority}` into a reserved `state.variables` key — NOT into the
  conversation log or `lastOutputs` (the pair is hidden from players). The
  validator + retry + fallback-to-static loop lives **inside the handler**: the
  DSL has no loop control and `conditional` is depth-1 boolean, so retry cannot
  be a separate downstream code phase.
- **`assign` gains a `source_variable:` mode**, mutually exclusive with static
  `source:`. Backward-compat: static `words:` + `source:` is unchanged, and
  `words:` stays **required** as the fallback pool and MockLLMService test
  fixture (deterministic success-path and breakage-fallback tests).
- **Category curation in `generate.categories:`** — a per-language,
  harness-vetted list; weak categories are excluded by omission.
- **Validator checks hardcoded** (normalize-equality, containment, blocklist,
  avoid-list); author config limited to `max_attempts` / `avoid` / `fallback`.
  Safety-critical checks are not YAML-disableable.
- **Cost caveat:** a new `PhaseType` ripples per
  `.claude/rules/engine.md` § "Adding a new `PhaseType`" — ADR-022
  no-default-exhaustive switches, the census CI gate, a
  `ScenarioConventions` primary/thought-field decision (a non-diegetic phase
  has no conversation-log primary field), and the round-trip fixture. This is
  non-trivial; "minimal engine change" undersells it. Before adding a type,
  weigh extending an existing single-call phase (the `narrate` single-inference
  non-participant precedent).

## Revisit trigger

Re-evaluate when a stronger on-device model lands with calibration + diversity +
script-robustness — i.e. the **LiteRT-LM migration** or a successor model (see
ADR-002 § 8.2 "Migration trigger fired — evaluation in progress", #496
model-migration eval). Re-run the same harness gate (n≈100 per category ×
language; require post-filter breakage 0 with the anti-homograph prompt rule).
Tracked under the #906 sim-interestingness umbrella.

## Alternatives considered

- **A — Pure mechanical validator + retry (no LLM judge).** Rejected: the three
  failure modes above; it cannot catch the dominant breakage classes
  (homograph, semantic part-of) and false-positive-kills good pairs
  (`Pen↔Pencil`).
- **B — Open-category generation (no fixed genre).** Rejected: ~16-20% usable;
  category *selection* runs away (hierarchy, non-words, pun-only links,
  too-far pairs).
- **C — Static pool expansion.** The near-term winner on variety, cost, and
  safety, and the fallback pool the deferred design needs anyway. Not done
  *now* only because the app is in first-review wait (no shipping value yet).
- **D — On-device LLM judge for calibration.** Deferred: adds latency and its
  own reliability question on a 2B model; revisit with a stronger model.
